## 一、学生应该学到的五件事

### 1. 这个框架在解决什么问题

CFU-Playground 把软核、SoC、TFLite Micro 和仿真搭好。学生要做的是给 VexRiscv 加一条指令，让热循环里反复出现的运算少退休一些指令，再用 `mcycle` 比较。

CFU 嵌在 CPU 流水线里。CPU 发一条 `CUSTOM0`，送进两个寄存器，拿回一个结果。CFU 不访问内存。循环、取数、累加仍由 CPU 完成。

它不是 NPU。NPU 在旁边跑一整层，可以排队、搬数据。CFU 是 CPU 停在这一条指令上等结果。

### 2. 一次按键穿过三层

以 `proj/my_first_cfu` 里菜单 `a` 为准，结果是 `22 + 22 = 44`。

| 层 | 在哪 | 这一次做了什么 |
|---|---|---|
| C | `src/proj_menu.cc` 的 `do_one_add` | 准备 22 和 22，打印结果 |
| 指令 | `common/src/cfu.h` 的 `cfu_op0` | 展开成一条 `CUSTOM0`，`funct3 = 0` |
| 电路 | `cfu.py` 的 `TemplateInstruction` | `output = in0 + in1`，生成 `cfu.v` |

学生要能用自己的话走完这三层，而不是只说「仿真跑起来了」。

### 3. 软件路径和硬件路径分叉在宏

`cfu_op3_sw` 调用 `software_cfu()`，在同一颗软核上跑 C 函数，循环里的每条 RISC-V 指令都计入 `mcycle`。

`cfu_op3_hw` 是一条自定义指令。Renode 执行到它就调用 `Cfu::execute()`，由 Verilator 按时钟更新 `cfu.v` 里的寄存器，把 `resp_data` 写回目标寄存器。

`Makefile` 里的 `CFU_SOFTWARE_DEFINED` 只改不带 `_hw` / `_sw` 后缀的 `cfu_op`。`my_first_cfu` 里这行是注释掉的，所以 `cfu_op0` 走电路。

### 4. 仿真抽象掉了主机，没有抽象掉软核的拍

现在这台电脑执行的是 x86。Renode 是解释执行：取一条 RISC-V 客机指令，在模型里改寄存器和 `mcycle`。它不像 QEMU 那样把一段 RISC-V 翻译成一段 x86 再缓存。

`mcycle` 数的是模型里这颗 VexRiscv 退休了多少拍，不是主机的 x86 拍，也不是墙钟。软件循环的拍数和板上同一颗软核是对齐的。

多拍 CFU 是例外。斐波那契状态机在 Verilator 里按 `n` 走了，但这 `n` 拍没有加进 Renode 的 `mcycle`，所以 `n = 10` 和 `n = 40` 的硬件读数都是 3。放到 FPGA 上，CPU 停到 `rsp.valid`，这些等待拍才会进 `mcycle`。

### 5. 怎样才算验证了加速

先看两边结果是不是同一个数。再比同一段工作的 `mcycle` 差，不比两次启动后的绝对读数，也不比终端里的 host 时间。

两种有效情况：

- 电路当拍做完，一条指令换掉多条 RISC-V 指令。少掉的指令会进 Renode 的 `mcycle`。GEMM 的 `Dot4` 就是这样：8×8×8 跑 20 遍，纯 C **34345** 拍，CFU **11943** 拍，校验和都是 960。
- 电路自己要跑很多拍（斐波那契）。软件侧 Renode 的斜率有效，大约每轮 5 拍；硬件侧要数状态机的时钟，大约 `n` 拍再加几拍握手。这个差要在板上读 `mcycle` 才完整。

没有变快的电路也是有效结论。状态机若比被换掉的那串指令还长，周期不会下降。

## 三、明天 5–8 分钟怎么讲

1. **问题。** 热循环里大量时间花在重复的整数运算上。这个框架允许给软核加一条指令，用电路做掉其中几步。
2. **接口。** 两个寄存器进，一个结果出，不访存。用 `my_first_cfu` 的 `22 + 22 = 44` 演示。
3. **两条路。** 同一条宏，软件进 C 函数，硬件进 `cfu.v`。斐波那契的结果一致，说明两边算的是同一件事。
4. **怎么判断变快。** `mcycle` 是软核的拍。GEMM 从 34345 到 11943，是因为 512 次标量乘法变成 128 条自定义指令。斐波那契的硬件 3 拍不能当成加速比。
5. **仿真的位置。** 主机跑的是 x86。Renode 解释 RISC-V。Verilator 把电路编成程序来更新 0 和 1。板上没有这层，电路自己就是软核。
6. **和 NPU、专用芯片的关系。** 标准模型拼吞吐，NPU 更合适。CFU 用来试一条指令的结构，量的是每条结果几拍。频率和能效要上板或做成芯片才算。

## 四、老师如果追问

**CFU 和函数调用有什么不同？**  
`cfu_op0(...)` 看起来像函数，展开后是一条内联指令，不是函数指针，也没有把 C 函数注册到 FPGA 上。

**为什么 x86 上两边墙钟不能比？**  
墙钟是主机跑仿真的时间。`mcycle` 才是软核模型的拍。两边在 x86 上干的活不一样。

**没有板，Step-by-Step 还能做什么？**  
复制工程、跑 `pdti8` 看软件周期、改 C 循环、写当拍完成的 CFU 并看指令变少。不能做比特流和时序。

**学生做完应能独立完成的最小动作。**  
在自己的工程里加一条当拍完成的整数指令，菜单里用固定输入打出结果，并说明它替掉了哪几条 RISC-V 指令。`my_first_cfu` 的加法已经是这个最小动作。
