# 学完后的目标（毕业标准）

一句话：你能把 **stories15M 的一次前向**从 `run.c` 里的一块内存，写成自己的 C++ 引擎，用 token 和延迟证明 KV cache 与 AVX2 各自做了什么，并能在 tiny-cnn 和 llama.cpp 里指出算子抽象、内存池、量化块。

这是「推理基础设施入门毕业」，不是「CUDA 内核工程师」或「在线推理平台工程师」毕业。

---

## 你必须能独立做到的事

1. **讲清一次前向在算什么**  
   不看资料按顺序列出 embedding、RMSNorm、QKV、RoPE、因果注意力、门控 FFN、logits。能代入 Config 算出某一层 `wq` 的起始下标。

2. **拥有一份对拍过的 C++ 实现**  
   `engine/` 用 RAII 持有权重和激活。Tensor 视图不拷贝权重。greedy 16 token 与 llama2.c 一致。

3. **用数字区分两种加速**  
   AVX2 相对朴素 GEMV：有 max abs diff，有延迟。KV cache 相对整段重算：token 一致，序列拉长后生成时间更短。decode 一步是 GEMV，带宽先于峰值算力。

4. **看得出框架在组织什么**  
   在 tiny-cnn 里指出热路径的模板分发和数据布局，并按同样风格加一个 RMSNorm。

5. **读得懂工业代码的骨架（口试必过）**

   | 你在 llama.cpp 里指向的东西 | 它组织的是 |
   |------------------------------|------------|
   | 张量 + 分配器 + 计算图 | 先描述计算，再分配，再执行 |
   | KV cache | 第 t 步不必重算历史 K/V |
   | Q8_0 / Q4_0 的 block | 用更少字节换带宽，并付出精度 |

6. **同一套小权重走完主干**  
   llama2.c 参照、无 cache C++、AVX2、带 cache 的 C++。进阶再留下 tiny-cnn 的 RMSNorm 测试和量化 block 的字节账。

## 毕业口试（闭卷，全答上才算学完）

1. RunState 里哪些缓冲可以每层复用？第 0 层 `wq` 的起始元素下标怎么算？
2. 第 t 步 decode 为什么不必重算 1…t-1 的 K/V？RoPE 的位置下标取几？
3. 你的 AVX2 相对朴素 GEMV：max abs diff 和延迟各是多少？这一步的瓶颈在算力还是带宽？
4. 热路径为什么用模板分发？一个 Q4 或 Q8 block 相对 fp32 省下的字节从哪来？
5. 读 vLLM 或 TensorRT 之前，你已经能在 llama.cpp 里指出哪三段（张量/图/内存池、KV、量化布局）？

## 学完在真实世界能干什么

这门课给你的是**推理计算和内存的读写能力**。

**马上能做的事**

- 把「CPU 上生成很慢」拆开：在重算历史、在用朴素 GEMV、权重没有对齐、还是根本走错了框架。
- 用自己的 `engine/` 当作品：有参照实现、有 token 对拍、有延迟表。
- 读 llama.cpp 的 issue 和文档时，知道对方在说张量、图、KV 还是量化格式。
- 和写 PyTorch 的同学对齐：他们在图里看到的 Linear，你能指到一块行主序权重和一次 GEMV。

**L13 主干结束后就能做**

- 在小模型上改一版算子并证明没有改坏生成结果。适合先交差，再决定要不要读工业代码。

**L20 全计划结束后更能做**

- 继续往下：Q8 GEMV、分块 GEMM、变长 batch，或对照 llama.cpp 的一个 CPU 算子。
- 再进入 `llms-zth` 里的服务调度、ONNX、TensorRT 时，知道那些运行时优化的是哪一层。

**仍然不能直接做的**

- 独立负责公司级 GPU 推理集群。
- 顶替高性能内核组的 CUDA 工程师。
